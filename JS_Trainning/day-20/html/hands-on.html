Task 1: Predict the Output

Write your predicted order in a comment before running. Then run and compare. Label each line as sync, microtask, or macrotask.

console.log("1");                                 // sync
setTimeout(() => console.log("2"), 0);            // ?
Promise.resolve().then(() => console.log("3"));   // ?
console.log("4");                                 // sync

// PREDICT before running — what order will 1, 2, 3, 4 appear?
// YOUR PREDICTION: ?

// ACTUAL output: 1, 4, 3, 2
// Labels:
//   "1" → sync (call stack)
//   "2" → macrotask (setTimeout callback)
//   "3" → microtask (Promise.then callback)
//   "4" → sync (call stack)

Task 2: Two Promises and a Timer

Predict the full output order, then run and compare. In a comment, draw the microtask and macrotask queues at each step.

console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve()
  .then(() => console.log("C"))
  .then(() => console.log("D"));

queueMicrotask(() => console.log("E"));

console.log("F");

// PREDICT: ?

// ACTUAL: A, F, C, E, D, B
//
// Queue walk-through:
//   After sync (A, F):
//     Microtask queue: [C callback, E callback]
//     Macrotask queue: [B callback]
//
//   Run C → schedules D as next microtask
//     Microtask queue: [E callback, D callback]
//     Macrotask queue: [B callback]
//
//   Run E
//     Microtask queue: [D callback]
//     Macrotask queue: [B callback]
//
//   Run D — microtask queue now empty
//     Macrotask queue: [B callback]
//
//   Run B — one macrotask per loop tick

Task 3: Block the Loop

Write blockFor(ms) using a while loop and Date.now(). Schedule a timer for 100 ms, then call blockFor(2000). Confirm the timer fires well after 2 seconds, not after 100 ms.

function blockFor(ms) {
  const t0 = Date.now();
  while (Date.now() - t0 < ms) {}   // busy-wait — holds the stack for `ms` ms
}

const start = Date.now();

setTimeout(() => {
  // This was scheduled for 100ms but can't run until the stack clears
  console.log(`timer fired at ${Date.now() - start}ms`);   // ~2000ms, not 100ms
}, 100);

blockFor(2000);                      // blocks everything for 2 seconds
console.log(`after block at ${Date.now() - start}ms`);

// Output:
//   after block at ~2000ms
//   timer fired at ~2000ms   ← NOT 100ms; timer was queued but couldn't run

Bonus: Microtask Storm

Schedule 5 setTimeout(fn, 0) calls. Inside timer #3, schedule 3 Promise.resolve().then(...) callbacks. Predict the full output, then run. In a comment, explain how uncontrolled microtask recursion can starve macrotasks.

for (let i = 1; i <= 5; i++) {
  setTimeout(() => {
    console.log(`timer ${i}`);

    if (i === 3) {
      // Three microtasks injected mid-macrotask-run
      Promise.resolve().then(() => console.log("micro A"));
      Promise.resolve().then(() => console.log("micro B"));
      Promise.resolve().then(() => console.log("micro C"));
    }
  }, 0);
}

// Output:
//   timer 1
//   timer 2
//   timer 3
//   micro A    ← microtasks drain before timer 4 gets its turn
//   micro B
//   micro C
//   timer 4
//   timer 5
//
// COMMENT: Microtask starvation
//   If a microtask schedules another microtask, and that one schedules another,
//   the microtask queue never empties and the macrotask queue (UI events,
//   timers, rendering) is completely starved. The page freezes even though
//   the call stack isn't occupied by one long function — it's occupied by an
//   endless chain of microtasks. Use setTimeout(0) to deliberately yield
//   to the macrotask queue when doing recursive async work.
