Performance & Best Practices

The final session. You already know the language — today is about shipping code that stays fast, stays safe, and stays readable as it grows.

Topic 1: Debounce vs Throttle

High-frequency events like input, scroll, and mousemove can fire hundreds of times per second. Running expensive work on every event tanks performance. Two complementary tools tame them.

ToolBehaviourBest for
DebounceWait until the user stops, fire onceSearch input, autosave, resize
ThrottleFire at most once per N msScroll, mousemove, drag
 
// DEBOUNCE — only fire after `delay` ms of silence
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// THROTTLE — fire at most once per `delay` ms
function throttle(fn, delay) {
  let lastCall = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastCall < delay) return;
    lastCall = now;
    fn.apply(this, args);
  };
}

// Usage — search input debounced at 300 ms
const handleSearch = debounce((q) => {
  console.log("searching for:", q);
}, 300);
input.addEventListener("input", (e) => handleSearch(e.target.value));

// Usage — scroll throttled to 100 ms
const onScroll = throttle(() => {
  console.log("scroll at", window.scrollY);
}, 100);
window.addEventListener("scroll", onScroll);

Follow-along — predict the output:

const log = debounce(() => console.log("fired"), 100);
log(); log(); log();
// wait 200 ms
log();
// → how many fires?

Answer: twice — once after the first burst settles, once after the final call.

Topic 2: Memory Leaks — The Big Four

// 1. Forgotten globals
function leaky() {
  user = { name: "Priya" };       // no let/const → attaches to globalThis
}
// FIX: always use let/const. Use "use strict" or ES modules (strict by default).

// 2. Forgotten timers / intervals
const id = setInterval(() => doStuff(), 1000);
// If the component owning this never calls clearInterval(id), it leaks.
// FIX: always pair setInterval with clearInterval on cleanup.
clearInterval(id);

// 3. Detached DOM nodes held by event listeners
const btn = document.querySelector("#save");
btn.addEventListener("click", () => doSave());
btn.remove();
// btn is removed from the DOM but the listener still holds a JS reference.
// FIX: removeEventListener before remove(), or use AbortController:
const ctrl = new AbortController();
btn.addEventListener("click", handler, { signal: ctrl.signal });
ctrl.abort();   // cleans up the listener too

// 4. Closures holding large data
function makeHandler(largeData) {
  return function () {
    return largeData.length;          // closure keeps largeData alive forever
  };
}
// FIX: extract only what you need.
function makeHandler(largeData) {
  const len = largeData.length;
  return function () { return len; };
}

Topic 3: Garbage Collection

JS engines use tracing GC (mark-and-sweep). Starting from roots — globals, the call stack, active closures — the engine walks every reachable object. Anything unreachable is eligible for collection.

Modern engines add generational GC: short-lived objects are collected in the fast young generation; long-lived objects graduate to the slower old generation. You control GC indirectly by controlling reachability — nullifying a reference (myRef = null) lets the engine collect that object when nothing else points to it.

NetworkRequests and their timing

Tag your own code with the User Timing API so your measurements appear in the timeline alongside browser events:

performance.mark("compute-start");
expensiveComputation();
performance.mark("compute-end");
performance.measure("compute", "compute-start", "compute-end");
// "compute" now appears as a band in the DevTools Performance recording.

Topic 5: Security — XSS, eval, Sanitisation

// 1. XSS via innerHTML — all-time #1 web vulnerability
const userComment = '<img src=x onerror="alert(\'pwned\')">';

// UNSAFE — runs the attacker's onerror handler
commentEl.innerHTML = userComment;

// SAFE — treats it as plain text, no parsing
commentEl.textContent = userComment;

// If you MUST insert HTML, sanitise first (DOMPurify is the standard):
commentEl.innerHTML = DOMPurify.sanitize(userComment);


// 2. eval() and the Function constructor — never use with user input
const userExpr = "alert('exploited')";
// NEVER: eval(userExpr);
// NEVER: new Function(userExpr)();
// Both execute arbitrary code with full page privileges.


// 3. Safe JSON parsing
const safe = JSON.parse(serverJSON);   // ✅ safe — no code execution

⚠️ React note: React escapes {'{value}'} by default — safe. dangerouslySetInnerHTML bypasses that. The name is the warning. Always sanitise with DOMPurify before passing to it.
