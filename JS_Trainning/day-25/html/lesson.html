Functional Programming

Functional programming (FP) is a style of writing JavaScript where you build programs out of small, pure, composable functions — avoiding shared state and mutation. It makes code more predictable, testable, and easier to reason about.

Topic 1: Pure Functions

A function is pure if (1) the same input always produces the same output, and (2) it has no side effects — no I/O, no DOM access, no mutation of anything outside itself.

// PURE — no external state, no side effects
function add(a, b) { return a + b; }
function withGST(price, rate = 18) { return price * (1 + rate / 100); }

// IMPURE — depends on external state (multiplier could change)
let multiplier = 2;
function impureDouble(x) { return x * multiplier; }

// IMPURE — mutates the argument
function addItem(arr, item) {
  arr.push(item);    // mutates input!
  return arr;
}

// PURE version — return a NEW array instead
function addItemPure(arr, item) {
  return [...arr, item];
}
PropertyPureImpure
Same input → same output✓ Yes✗ Maybe
Side effects✓ None✗ Allowed
Mutates input✓ No✗ Maybe
Reads external state✓ No✗ Yes

Topic 2: Side Effects at the Edges

Keep the core of your code pure. Push all I/O (network, DOM, logging) to the outermost shell — this makes the business logic trivially unit-testable.

async function processOrder(orderId) {
  const order = await fetchOrder(orderId);       // side effect — edge (network)

  // ↓ pure transformations in the middle
  const validated = validate(order);
  const taxed     = applyTax(validated);
  const formatted = formatForDisplay(taxed);

  await saveOrder(formatted);                    // side effect — edge (network)
  await sendEmail(formatted.email, formatted);   // side effect — edge (email)
}

Topic 3: Higher-Order Functions

A higher-order function (HOF) either takes a function as an argument, returns a function, or both. You already use built-in HOFs every day: map, filter, reduce.

// HOFs that TAKE a function
const nums = [1, 2, 3, 4, 5];
nums.map((x) => x * 2);            // [2, 4, 6, 8, 10]
nums.filter((x) => x % 2 === 0);   // [2, 4]
nums.reduce((a, b) => a + b, 0);   // 15

// HOF that RETURNS a function
function multiplier(factor) {
  return (x) => x * factor;
}
const double = multiplier(2);
console.log(double(5));   // 10

// HOF that TAKES and RETURNS — the `once` utility
function once(fn) {
  let called = false, result;
  return (...args) => {
    if (called) return result;
    called = true;
    return (result = fn(...args));
  };
}

const init = once(() => "initialised");
console.log(init());   // "initialised"
console.log(init());   // "initialised" — fn NOT called again

Follow-along — predict the output:

const m = (f) => (x) => f(x) * 2;
const inc = (x) => x + 1;
const incThenDouble = m(inc);
console.log(incThenDouble(5));   // → ?

Answer: inc(5) → 6, then 6 * 2 → 12.

Topic 4: compose and pipe

pipe runs functions left-to-right (readable, top-down). compose runs them right-to-left (math-style). Both are one-liners built on reduce.

const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);
const pipe    = (...fns) => (x) => fns.reduce     ((acc, fn) => fn(acc), x);

// Small pure functions
const trim      = (s) => s.trim();
const lower     = (s) => s.toLowerCase();
const split     = (s) => s.split(/\s+/);
const wordCount = (arr) => arr.length;

// Build the pipeline — reads like a recipe
const countWords = pipe(trim, lower, split, wordCount);
console.log(countWords("  Hello World from Jaipur  "));   // 4
FormDirectionStyle
compose(f, g)(x)f(g(x)) — right→leftMath-y
pipe(f, g)(x)g(f(x)) — left→rightReads top-down

Topic 5: Currying

Currying transforms fn(a, b, c) into fn(a)(b)(c). Each call returns a new function waiting for the next argument — great for pre-filling configuration values.

// Arrow shorthand — clean and concise
const addC = (a) => (b) => (c) => a + b + c;
addC(1)(2)(3);   // 6

// Practical — pre-fill the tax RATE, vary the PRICE later
const tax     = (rate) => (price) => price * (1 + rate / 100);
const withGST = tax(18);   // rate locked at 18
const withVAT = tax(10);   // rate locked at 10

console.log(withGST(1000));   // 1180
console.log(withVAT(1000));   // 1100

Topic 6: Partial Application

Partial application fixes some arguments of a function and returns a new function for the rest. Unlike currying, you can fix multiple args at once.

function greet(greeting, time, name) {
  return `${greeting} ${time}, ${name}!`;
}

// Using .bind (built-in)
const sayGoodMorning = greet.bind(null, "Good", "morning");
console.log(sayGoodMorning("Priya"));   // "Good morning, Priya!"

// Hand-rolled partial helper
const partial = (fn, ...preset) => (...rest) => fn(...preset, ...rest);

const sayHelloEvening = partial(greet, "Hello", "evening");
console.log(sayHelloEvening("Riya"));   // "Hello evening, Riya!"
PatternCode
Curry(a) => (b) => (c) => ...
Partial via bindfn.bind(null, a, b)
Partial helperpartial(fn, ...preset)

Topic 7: A Real-World Pipeline

Combine pure functions, pipe, and currying to process real data. Every step is independently testable.

const orders = [
  { id: 1, item: "Pen",  price: 50,  quantity: 2 },
  { id: 2, item: "Book", price: 200, quantity: 1 },
  { id: 3, item: "Bag",  price: 800, quantity: 1 },
  { id: 4, item: "Mug",  price: 150, quantity: 3 },
];

const lineTotal = (o)   => o.price * o.quantity;
const withGST   = (amt) => amt * 1.18;
const round2    = (n)   => Math.round(n * 100) / 100;
const formatINR = (n)   => `₹${n.toLocaleString("en-IN")}`;
const sum       = (a, b) => a + b;

const grandTotal = pipe(
  (orders) => orders.map(lineTotal),   // [100, 200, 800, 450]
  (totals) => totals.reduce(sum, 0),   // 1550
  withGST,                              // 1829
  round2,                               // 1829
  formatINR,                            // "₹1,829"
);

console.log(grandTotal(orders));        // "₹1,829"

One-liners to remember:

FunctionImplementation
pipe(...fns)=>(x)=>fns.reduce((a,f)=>f(a),x)
compose(...fns)=>(x)=>fns.reduceRight((a,f)=>f(a),x)
onceclosure flag + cached result
memoizeMap cache by args
