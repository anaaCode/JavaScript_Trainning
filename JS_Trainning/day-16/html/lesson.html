Prototypes & the Prototype Chain

Understanding how JavaScript objects inherit from one another through the hidden [[Prototype]] link, and the patterns that exploit it.

Topic 1: Every Object Has a Prototype

Every JS object has a hidden [[Prototype]] link pointing to another object. When you read a property not found on the object itself, JS follows that link and looks there.

const user = { name: "Priya" };

// Every object literal's prototype is Object.prototype
console.log(Object.getPrototypeOf(user) === Object.prototype);  // true

// user has no .toString() of its own — but it can call one!
console.log(user.toString());  // "[object Object]"

// toString lives on Object.prototype
console.log(Object.prototype.hasOwnProperty("toString"));  // true

// At the END of the chain: null
console.log(Object.getPrototypeOf(Object.prototype));      // null

// Chain:  user  →  Object.prototype  →  null
//        (name)    (toString, ...)    (end)

Topic 2: Object.create — Explicit Prototype Linking

Object.create(proto) creates a new object whose [[Prototype]] is set to proto. Own properties you add afterwards shadow inherited ones without mutating the prototype.

const animal = {
  eat()   { console.log(`${this.name} is eating`); },
  sleep() { console.log(`${this.name} is sleeping`); },
};

// dog inherits from animal
const dog = Object.create(animal);
dog.name = "Bruno";

dog.eat();    // "Bruno is eating"    ← method found on animal
dog.sleep();  // "Bruno is sleeping"  ← same path

console.log(Object.getPrototypeOf(dog) === animal);  // true
console.log(dog.hasOwnProperty("name"));  // true   ← on dog itself
console.log(dog.hasOwnProperty("eat"));   // false  ← inherited from animal

// Follow-along: walk the chain manually
const a = { x: 1 };
const b = Object.create(a);
b.y = 2;
console.log(b.x);                    // 1    ← inherited
console.log(b.y);                    // 2    ← own
console.log(b.hasOwnProperty("x")); // false

Topic 3: The Prototype Chain — Read Walks Up, Write Makes Own

Reading a property walks up the chain until found or null. Writing a property always creates (or updates) an own property on the object — the prototype is never mutated.

const grandparent = { lastName: "Sharma" };
const parent      = Object.create(grandparent);
parent.firstName  = "Priya";
const child       = Object.create(parent);
child.age         = 5;

// READ — walks up
console.log(child.age);        // 5         ← own
console.log(child.firstName);  // "Priya"   ← from parent
console.log(child.lastName);   // "Sharma"  ← from grandparent
console.log(child.toString);   // ƒ         ← from Object.prototype

// WRITE — creates own; prototype untouched
child.firstName = "Anaya";
console.log(child.firstName);   // "Anaya"  ← own property now shadows parent's
console.log(parent.firstName);  // "Priya"  ← prototype unchanged

// Chain: child → parent → grandparent → Object.prototype → null

Topic 4: hasOwnProperty vs in

Use obj.hasOwnProperty("x") (or the modern Object.hasOwn(obj, "x")) to check only the object's own properties. Use "x" in obj to search the entire chain.

const animal = { eat() {} };
const dog = Object.create(animal);
dog.bark = () => console.log("woof");

console.log(dog.hasOwnProperty("bark"));   // true   — dog has its own bark
console.log(dog.hasOwnProperty("eat"));    // false  — eat is inherited
console.log("bark" in dog);                // true   — found on dog
console.log("eat"  in dog);               // true   — found on animal (chain)
console.log("toString" in dog);           // true   — found on Object.prototype

// Modern, safer alternative to hasOwnProperty:
console.log(Object.hasOwn(dog, "bark"));  // true

Topic 5: Constructor Functions & Pre-ES6 Inheritance

Before ES6 classes, JS developers wired up inheritance manually using constructor functions, new, and Object.create. Understanding this explains exactly what classes do under the hood.

function User(name, city) {
  this.name = name;  // own property on the new object
  this.city = city;
}

// Methods go on the SHARED prototype — not duplicated per instance
User.prototype.greet = function () {
  console.log(`Hi, I'm ${this.name} from ${this.city}`);
};

const u1 = new User("Priya", "Jaipur");
const u2 = new User("Aarav", "Mumbai");
u1.greet();  // "Hi, I'm Priya from Jaipur"
u2.greet();  // "Hi, I'm Aarav from Mumbai"

console.log(u1.greet === u2.greet);  // true — one shared function

// Inheritance — Admin extends User
function Admin(name, city, level) {
  User.call(this, name, city);              // borrow User's constructor
  this.level = level;
}
Admin.prototype = Object.create(User.prototype);  // chain Admin → User
Admin.prototype.constructor = Admin;              // restore constructor pointer

Admin.prototype.power = function () {
  console.log(`${this.name} has level ${this.level}`);
};

const ad = new Admin("Riya", "Bangalore", 5);
ad.greet();  // "Hi, I'm Riya from Bangalore" ← inherited from User.prototype
ad.power();  // "Riya has level 5"            ← own to Admin.prototype

⚠️ This is the old way — verbose and easy to get wrong. ES6 classes compress it into a few lines, but they compile down to exactly this pattern.

Topic 6: Don't Modify Built-in Prototypes

Adding to Array.prototype, String.prototype, etc. affects every instance everywhere — including inside third-party libraries you import. Future ECMAScript versions may also add the same method name, causing silent breakage.

// ❌ DON'T do this in real code
// Array.prototype.last = function () { return this[this.length - 1]; };
// Problems:
// 1. Every Array in every imported library now has .last
// 2. A future JS spec may add .last with a different behaviour
// 3. for...in over an array may iterate over 'last' unexpectedly

// ✅ SAFER — a plain utility function
function last(arr) { return arr[arr.length - 1]; }
const fruits = ["apple", "mango", "banana"];
console.log(last(fruits));  // "banana"

Topic 7: Mental Model — Bringing It Together

Three rules cover almost every prototype question:

// 1. Property READ  → walk up the chain until found or null
// 2. Property WRITE → create an own property; prototype untouched
// 3. Method CALL    → method located via chain; 'this' = object called on

// Quick reference
Object.create(proto)          // new object with [[Prototype]] = proto
Object.getPrototypeOf(obj)    // returns obj's prototype
obj.hasOwnProperty("k")       // true only if k is DIRECTLY on obj
Object.hasOwn(obj, "k")       // modern, safe version of hasOwnProperty
"k" in obj                    // true if k is ANYWHERE in the chain
