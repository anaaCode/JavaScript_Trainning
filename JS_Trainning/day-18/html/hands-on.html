Hands-On Tasks

Task 1: Sync vs Async Output

Predict the output order before running, then run and verify. In a comment, explain why D appears before B even though both are "async with delay 0".

console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
Promise.resolve().then(() => console.log("D"));

// Predict the order: A, ?, ?, ?
// Then run it. Were you right?
// COMMENT: Why does D come before B?
//   setTimeout callbacks go into the macrotask queue.
//   Promise .then callbacks go into the microtask queue.
//   Microtasks are drained completely before the next macrotask runs.
//   So: A (sync) → C (sync) → D (microtask) → B (macrotask)

Task 2: Promisify a Callback API

Wrap the given callback-style function in a Promise-returning version, then chain three logs: "1" after 300 ms, "2" after 200 ms more, "3" after 100 ms more.

// Given callback-style function
function delayLog(msg, ms, cb) {
  setTimeout(() => { console.log(msg); cb(null); }, ms);
}

// Your task: write delayLogPromise(msg, ms) that returns a Promise
function delayLogPromise(msg, ms) {
  return new Promise((resolve, reject) => {
    delayLog(msg, ms, (err) => {
      if (err) reject(err);
      else resolve();
    });
  });
}

// Chain three sequential logs
delayLogPromise("1", 300)
  .then(() => delayLogPromise("2", 200))
  .then(() => delayLogPromise("3", 100))
  .then(() => console.log("all done"));

Task 3: Promise.all in Action

Write a fetchPrice(item, ms) function that resolves to a price object after ms milliseconds. Use Promise.all to fetch all three in parallel, sum the prices, and log the total. Time the whole thing with Date.now() and confirm the elapsed time is near the slowest item, not the sum of all delays.

// Data: pen → 50 (300ms), book → 200 (500ms), bag → 800 (400ms)
function fetchPrice(item, ms) {
  const prices = { pen: 50, book: 200, bag: 800 };
  return new Promise((resolve) => {
    setTimeout(() => resolve({ item, price: prices[item] }), ms);
  });
}

const start = Date.now();

Promise.all([
  fetchPrice("pen",  300),
  fetchPrice("book", 500),
  fetchPrice("bag",  400),
]).then((results) => {
  const total = results.reduce((sum, r) => sum + r.price, 0);
  const elapsed = Date.now() - start;
  console.log("Total:", total);          // 1050
  console.log("Time (ms):", elapsed);    // ~500 — the slowest, not 300+500+400=1200
});

Bonus: Promise.allSettled vs Promise.all

Run the three promises below first with Promise.all, then with Promise.allSettled. In a comment, explain when you would reach for each.

const ok1 = Promise.resolve("ok1");
const bad  = Promise.reject(new Error("fail"));
const ok2  = Promise.resolve("ok2");

// With Promise.all — what happens?
Promise.all([ok1, bad, ok2])
  .then((values) => console.log("all:", values))
  .catch((err)   => console.log("all caught:", err.message));
// → "all caught: fail"  — one rejection kills the whole batch

// With Promise.allSettled — what happens?
Promise.allSettled([ok1, bad, ok2])
  .then((results) => results.forEach((r) => console.log(r.status, r.value ?? r.reason)));
// → fulfilled "ok1" | rejected Error("fail") | fulfilled "ok2"

// COMMENT: When to use which?
//   Promise.all   → you need ALL results; any failure means you can't continue
//   Promise.allSettled → you want every outcome regardless; e.g. batch uploads
//                        where you report success/failure per item
