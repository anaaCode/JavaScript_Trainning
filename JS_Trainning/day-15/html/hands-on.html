Hands-on Tasks

Complete these tasks during class. Predict the output first, then run it.

Task 1: Predict the this

What to do:

  • Type the snippet below exactly — a user object with name: "Priya" and a method greet() that logs this.name
  • Predict what each call prints before running
  • Run it and note the actual output
  • In a comment, explain why the second call lost this
const user = {
  name: "Priya",
  greet() { console.log(this.name); },
};

user.greet();        // predict first → "Priya"

const g = user.greet;
g();                 // predict first → undefined (strict) / "" (non-strict)

// Why g() lost this:
// user.greet() uses implicit binding — this = user
// const g = user.greet pulls the function off the object.
// g() is a plain call — default binding applies — this is no longer user.

Task 2: Fix the Lost this — Three Ways

What to do:

  • Take the Timer class below and run it — observe the TypeError
  • Fix it THREE different ways: .bind, arrow wrapper, and class field arrow
  • Verify all three log 1, 2, 3, …
class Timer {
  constructor() { this.sec = 0; }
  tick() { this.sec++; console.log(this.sec); }
}

const t = new Timer();

// BUG — this is lost when tick is passed as a plain reference
// setInterval(t.tick, 1000);  // TypeError: cannot read 'sec' of undefined

// FIX 1 — .bind: permanently bind this to t
setInterval(t.tick.bind(t), 1000);
// this is locked to t — works even when called as a plain function

// FIX 2 — Arrow wrapper: t.tick() is called as a method, so this = t
setInterval(() => t.tick(), 1000);
// the arrow itself doesn't care about this — it just calls t.tick() as a method

// FIX 3 — Class field arrow: tick is defined as an arrow, lexical this = instance
class TimerArrow {
  sec = 0;
  tick = () => { this.sec++; console.log(this.sec); };
}
const ta = new TimerArrow();
setInterval(ta.tick, 1000);  // works — arrow's this is always the instance

Task 3: call / apply / bind

What to do:

  • Create const u = { name: "Aarav" }
  • Call describe with u as this using .call, then .apply
  • Create a bound version with .bind that pre-fills role to "developer" and call it
  • In a comment, write the one-line difference between the three
function describe(role, city) {
  console.log(`${this.name} is a ${role} from ${city}`);
}

const u = { name: "Aarav" };

// .call — invoke NOW, args listed
describe.call(u, "developer", "Mumbai");
// "Aarav is a developer from Mumbai"

// .apply — invoke NOW, args as array
describe.apply(u, ["developer", "Mumbai"]);
// "Aarav is a developer from Mumbai"

// .bind — returns NEW function, role pre-filled, called later
const describeAarav = describe.bind(u, "developer");
describeAarav("Mumbai");    // "Aarav is a developer from Mumbai"
describeAarav("Bangalore"); // "Aarav is a developer from Bangalore"

// One-line difference:
// .call invokes now with listed args | .apply invokes now with array args | .bind returns a new function for later

Bonus: Arrow vs Regular Method

What to do:

  • Build the team object with members: ["Priya", "Aarav", "Riya"] and two methods
  • printRegular() uses forEach(function(m) { ... }) — a regular function callback
  • printArrow() uses forEach((m) => { ... }) — an arrow function callback
  • Call both. Note which one breaks and explain why in a comment
const team = {
  members: ["Priya", "Aarav", "Riya"],

  // Regular function callback — gets its OWN this (undefined in strict mode)
  printRegular() {
    this.members.forEach(function (m) {
      console.log(this.members.length, m);  // TypeError — this is undefined here
    });
  },

  // Arrow function callback — inherits this from printArrow → which is team
  printArrow() {
    this.members.forEach((m) => {
      console.log(this.members.length, m);  // works: 3 Priya / 3 Aarav / 3 Riya
    });
  },
};

// team.printRegular();  // TypeError: cannot read 'members' of undefined
team.printArrow();       // 3 Priya  /  3 Aarav  /  3 Riya

// printRegular breaks because a regular function callback gets its own this.
// In strict mode that this is undefined — not the team object.
// printArrow works because arrow functions inherit this from the surrounding
// method (printArrow), whose this IS team.
