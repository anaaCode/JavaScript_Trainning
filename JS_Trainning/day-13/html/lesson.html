Execution Context & Hoisting

Understanding how JavaScript reads and runs your code — creation phase, execution phase, call stack, and why hoisting matters.

Topic 1: Execution Context

Every time JavaScript runs code it creates an Execution Context. The Global EC is created once. A Function EC is created fresh on every function call.

const city = "Jaipur";

function greet(name) {
  const message = "Hi " + name + " from " + city;
  return message;
}

greet("Priya");   // creates Function EC #1, then destroys it
greet("Aarav");   // creates Function EC #2 (fresh)

Topic 2: Two Phases — Creation & Execution

Before running any line, the engine does a Creation Phase — scans all declarations and allocates memory. Then the Execution Phase runs code top-to-bottom.

console.log(name);     // undefined  (memory exists, value not set yet)
var name = "Priya";
console.log(name);     // "Priya"

// CREATION PHASE:  name → undefined
// EXECUTION PHASE: line 1 logs undefined, line 2 assigns "Priya", line 3 logs "Priya"

Topic 3: The Call Stack

The call stack tracks which EC is running. Function called → pushed. Function returns → popped. Global EC stays at the bottom until the script ends.

function multiply(a, b) { return a * b; }
function square(n) { return multiply(n, n); }
function printSquare(n) { console.log(square(n)); }

printSquare(5);   // logs 25

// Call stack when multiply(5,5) is running:
// ┌──────────────────────────┐
// │  multiply(5, 5)          │  <-- top
// ├──────────────────────────┤
// │  square(5)               │
// ├──────────────────────────┤
// │  printSquare(5)          │
// ├──────────────────────────┤
// │  Global EC               │  <-- bottom
// └──────────────────────────┘

Topic 4: Hoisting

Hoisting is the result of the Creation Phase. var gets memory + undefined. let/const get memory but stay uninitialised (TDZ). Function declarations get their full body.

console.log(a);        // undefined          ← var hoisted with undefined
var a = 1;

// console.log(b);     // ReferenceError     ← let in TDZ
// let b = 2;

greet();               // "Hi"               ← full function body hoisted
function greet() { console.log("Hi"); }

Topic 5: var vs let / const + TDZ

The Temporal Dead Zone is the window between the start of the block and the let/const declaration line. Accessing it throws a ReferenceError.

console.log(score);    // undefined  ← var: no error, but not what you wanted
var score = 90;

// console.log(level);  // ReferenceError: Cannot access 'level' before initialization
// let level = 5;

{
  // console.log(mark);  // would throw — mark is in TDZ here
  let mark = 87;
  console.log(mark);    // 87 ← TDZ has ended
}

Topic 6: Function Declaration vs Expression

Function declarations are fully hoisted. Function expressions assigned to var are hoisted as undefined (TypeError on call). Those assigned to const/let are in the TDZ (ReferenceError on call).

sayHi();           // "Hi"  ← full body hoisted
function sayHi() { console.log("Hi"); }

greet();           // TypeError: greet is not a function
var greet = function () { console.log("Hello"); };

welcome();         // ReferenceError: Cannot access 'welcome' before initialization
const welcome = function () { console.log("Welcome"); };

shout();           // ReferenceError
const shout = () => console.log("HEY");
