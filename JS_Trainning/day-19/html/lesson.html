Async / Await

async / await is syntactic sugar over Promises. It lets you write asynchronous code that reads top-to-bottom like synchronous code — no chains, no callbacks.

Topic 1: async Functions Always Return a Promise

Marking a function async wraps its return value in a resolved Promise automatically. Even a plain return "hello" becomes Promise.resolve("hello").

async function greet() {
  return "Namaste";            // plain return — but...
}

const result = greet();
console.log(result);           // Promise { "Namaste" }  ← it's a Promise!

result.then((msg) => console.log(msg));  // "Namaste"

// Equivalent without async sugar:
function greetOld() {
  return Promise.resolve("Namaste");
}

Topic 2: await Pauses the async Function

await can only be used inside an async function (or at the top-level of an ES module). It pauses that function until the Promise settles — the rest of the program keeps running normally.

function fetchUser(id) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ id, name: "Priya" }), 500);
  });
}

// .then style
function withThen() {
  fetchUser(7).then((user) => {
    console.log("got:", user);
  });
}

// async/await style — reads like sync code
async function withAwait() {
  const user = await fetchUser(7);   // pause here for ~500ms
  console.log("got:", user);          // then continue
}

withAwait();

Topic 3: try / catch for Async Errors

A rejected Promise that is awaited throws inside the async function — so the familiar try / catch / finally pattern works exactly as it does for synchronous errors.

function fetchUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id < 0) reject(new Error("Bad id"));
      else         resolve({ id, name: "Priya" });
    }, 300);
  });
}

async function showUser(id) {
  try {
    const user = await fetchUser(id);
    console.log("got:", user);
  } catch (err) {
    console.error("failed:", err.message);
  } finally {
    console.log("done");   // always runs
  }
}

showUser(7);    // got: { id: 7, name: "Priya" } / done
showUser(-1);   // failed: Bad id                / done

Topic 4: Sequential vs Parallel

Three separate awaits run one-after-another — total time is the sum of all delays. Wrapping them in Promise.all starts all three at once — total time is the slowest delay only. Use sequential only when each step depends on the previous result.

function fetchProduct(id) {
  return new Promise((res) => setTimeout(() => res({ id, price: 100 }), 1000));
}

// SLOW — sequential (3 seconds total)
async function slow() {
  const t0 = Date.now();
  const a = await fetchProduct(1);   // wait 1s
  const b = await fetchProduct(2);   // then 1s more
  const c = await fetchProduct(3);   // then 1s more
  console.log(`Took ${Date.now() - t0}ms`);  // ~3000ms
}

// FAST — parallel (1 second total)
async function fast() {
  const t0 = Date.now();
  const [a, b, c] = await Promise.all([  // all three start immediately
    fetchProduct(1),
    fetchProduct(2),
    fetchProduct(3),
  ]);
  console.log(`Took ${Date.now() - t0}ms`);  // ~1000ms
}

Topic 5: The forEach Trap

forEach does not await the Promise returned by its async callback — the loop finishes instantly and the awaited work runs in the background untracked. Use for...of for sequential processing or Promise.all + map for parallel.

const ids = [1, 2, 3];

// BUG — forEach ignores the returned Promise
async function bug() {
  ids.forEach(async (id) => {
    const p = await fetchProduct(id);   // Promise returned but ignored
    console.log("got", p);
  });
  console.log("end");  // logs BEFORE any "got"
}

// FIX 1 — for...of (sequential, ordered)
async function sequential() {
  for (const id of ids) {
    const p = await fetchProduct(id);
    console.log("got", p);
  }
  console.log("end");  // logs AFTER all "got"
}

// FIX 2 — Promise.all + map (parallel, preferred)
async function parallel() {
  const results = await Promise.all(
    ids.map((id) => fetchProduct(id)),   // each returns a Promise; map collects them
  );
  results.forEach((p) => console.log("got", p));
  console.log("end");
}

Topic 6: Top-Level await

In ES modules (type="module" or .mjs), await can be used at the top level with no wrapping async function. In regular scripts it is a syntax error — use an immediately-invoked async function (IIFE) instead.

// In an ES module — top-level await is valid
const response = await fetch("/api/config");
const config   = await response.json();
console.log("Config loaded:", config);

// In a regular script — wrap in an async IIFE
(async () => {
  const r = await fetch("/api/config");
  const c = await r.json();
  console.log(c);
})();

Topic 7: Mixing async with .then

An async function returns a real Promise, so callers can use either .then chaining or await — both work identically. Pick whichever reads cleanest at the call site.

async function getUserName(id) {
  const user = await fetchUser(id);
  return user.name;   // resolves the returned Promise with user.name
}

// Caller using .then style
getUserName(7).then((name) => console.log(name));

// Caller using await style
(async () => {
  const name = await getUserName(7);
  console.log(name);
})();
